## 4. Claims I Cannot Support (And Why)

1. **"The chat endpoint provides real-time SSE streaming time-to-first-byte under 200ms."**
   - *Why*: The backend chat endpoint (`/api/chat`) is implemented strictly as a synchronous JSON POST returning full `ChatResponse`. It does not support Server-Sent Events or chunked transfer encoding.
2. **"Production RAG achieves an 80%+ retrieval hit rate against live database knowledge."**
   - *Why*: While the embedding cosine similarity algorithm achieves 90.00% top-3 hit rate against canonical vectors, the live Supabase PostgreSQL database `public.knowledge_chunks` table currently has **0 rows**, resulting in an effective hit rate of 0.00% in production until seed scripts are executed.
3. **"Multi-tenant chat message isolation is fully protected by Row Level Security (RLS) in the backend."**
   - *Why*: `ChatService.java` queries chat history via `chatMessageRepository.findTop20BySessionIdOrderByCreatedAtDesc(safeSessionId)` without constraining the query to the authenticated `profile.getId()`. An attacker supplying another user's `sessionId` can read the previous user's messages in their prompt context.
4. **"Baseline keyword safety filtering reliably catches self-harm and distress inquiries."**
   - *Why*: The baseline regex in `ChatService.java` missed **56.00%** of distress samples (28/50 missed), failing completely on Hinglish distress, typos, and indirect suicidal ideation.
5. **"Upstream Gemini LLM generation has sub-second response latency."**
   - *Why*: Real upstream Google Gemini API streaming calls measured a mean Time-to-First-Token of **5,248.25 ms** (p50: 4,766.09 ms, p95: 7,748.98 ms) with intermittent 503 Overloaded errors on `gemini-2.5-flash`.

1. **Streaming Time-to-First-Byte (TTFB) on Backend Pipeline**:
   - *Status*: **NOT MEASURED**
   - *Reason*: The Spring Boot `/api/chat` endpoint does not implement HTTP chunked streaming or Server-Sent Events (`text/event-stream`). It is a blocking JSON POST that buffers the complete Gemini synthesis before responding.
2. **Live Production Database Vector Hit-Rate**:
   - *Status*: **NOT MEASURED against production DB data**
   - *Reason*: Direct database inspection over TCP pooler confirmed `SELECT count(*) FROM knowledge_chunks` returned `0`. Retrieval hit-rate was evaluated against the canonical 13-chunk knowledge corpus locally.
3. **Multi-Tenant Postgres Row-Level Security (RLS) Enforcement**:
   - *Status*: **NOT MEASURED via Supabase RLS Policies**
   - *Reason*: The Spring Boot backend connects to Postgres using a single superuser/service connection (`postgres.lgcojtbcokecqmtyvsey`) which bypasses RLS policies. Isolation is handled purely at the application layer, which has the session ID isolation defect documented in Experiment G.
